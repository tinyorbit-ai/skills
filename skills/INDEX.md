# Skills index

Every skill in this repo, what it does, and the non-obvious parts of how it works.
This is the routing/orientation map for humans and the orphan check for
`evals/static/validate.mjs` — it is deliberately **not** in `CLAUDE.md`, because
each skill's `description` frontmatter is already always in the agent's context and
the table would be ~2,200 tokens of duplicate loaded every session.

Add a row here when you add a skill; the validator fails on a public skill with no
row, and on a row with no folder.

| Skill | Status | Description |
|---|---|---|
| `forge` | stable | Resumable orchestrator. `scripts/status.mjs --json` computes the stage and next action; routes init → discovery → plan → design (if UI) → harden → lock → build/review/ship one phase per run, or every phase with crack-on. `references/headless.md` holds the no-human rule, the Codex question tool and the `FORGE_RESULT` line every stage ends with. |
| `forge-principles` | stable | The quality bar: posture plus 12 rules, each led by one bold sentence. `scripts/card.mjs` turns the leads into `references/worker-card.md` (~180 words) that factories inject into every worker; the validator fails on a stale card. Rule 10 is the headless contract. |
| `forge-init` | stable | Scaffolds `wiki/` (record + `knowledge/` + `.forge/`) and injects the wiki/ADR/branch rules into CLAUDE.md and AGENTS.md. |
| `forge-discovery` | stable | Idea → `wiki/brief.md` through the base seven + sharpening six questions; runs `forge-scope` brief mode before the brief locks. |
| `forge-scope` | stable | Ambition and scope, merged from forge-ambition + forge-harden-scope. Brief mode (timid premises, bolder version, small unlocks) and plan mode (EXPAND / HOLD / TRIM). Every expansion names its proof burden and a paired cut or pressure valve; writes the `**Ambition check**` marker. |
| `forge-plan` | stable | Brief → risk-first `wiki/plan.md` with machine-read `## Phase N` blocks, goal-proving gates, seed ADRs and a release-closure phase. |
| `forge-design-system` | stable | Creates `DESIGN.md` from 2-3 named directions via a served specimen board. |
| `forge-design-explore` | stable | 3-4 rendered variants for one UI surface on a feedback board; locks the pick as an ADR and flips the phase to `**Design:** locked via [[decisions/NNNN]]`, which the build loop waits on. |
| `forge-harden` | stable | Plan hardening. Runs the eng, security, design and dx passes from its own `references/` as isolated subagents (or one pass with `forge-harden <persona>`), `forge-scope` on request, an economy sweep last, then a read-only adversary from another model family. Only the orchestrator asks the user. |
| `forge-build` | stable | Builds one phase on its branch to the forge-principles bar. |
| `forge-review` | stable | Staff review of a phase: passes 0-7 (scope, security, tests, strictness, edges, economy, runtime, adversary). Tests scoped by default, full suite when fast or shared code changed; a green re-run skips the passes but still runs the terminal block. |
| `forge-polish` | stable | Designer-eye QA on the running UI, run by forge-review. |
| `forge-dx` | stable | Live DX audit of a built CLI/API/SDK, run by forge-review. |
| `forge-ship` | stable | Rebase → gate on the rebased tree → build log, architecture, wiki upkeep and docs on the phase branch → one squash commit on base, or a PR with `--pr`. |
| `forge-docs` | stable | Diataxis drift check on the phase diff, run by forge-ship on the phase branch before landing. |
| `forge-debug` | stable | Root cause before fix, regression test, class guard, incident note. |
| `forge-retro` | stable | Retrospective over the build log and git since the last retro; files lessons and a `## Subtract` list. |
| `forge-wiki` | stable | Ask (cited), ingest (plan-first), ambient capture, and MAINTAIN: `scripts/wiki-maintain.mjs` regenerates every index and runs the mechanical health checks; the model writes Summary lines and judges duplicates. |
| `maximum-effort` | stable | Frontier-led task runner optimized for accepted quality per token. An Opus 5.5 or gpt-6-sol owner (medium by default, xhigh for L or risky work) owns judgment, integration, and the final result; Sonnet 5 at xhigh or gpt-6-luna at max handles bounded factual scouting and exact reversible edits with locked behavior and deterministic checks. `scripts/install-codex-profiles.sh` writes the three tiers as `codex exec -p me-mechanic|me-owner|me-hard` profiles. Delegation must cost less than direct execution, risky work stays frontier-owned, and a weak-model failure triggers immediate owner takeover rather than another repair round. L uses `.maximum-effort/plan.md`; Forge may use the same leaf-allocation policy without giving up its wiki, phase, gate, or ship lifecycle. Hands PRs to `lizard` and `shepherd`. |
| `lizard` | stable | AI PR reviewer, one binary verdict — an approval's entire body is 🦎 (see a lizard → merge; no other emoji anywhere, receipts included). Triage tiers (quick / standard / deep with multi-agent fan-out + cross-model adversary via codex/claude; runtime dep upgrades always deep + consumer matrix), "not proven safe ≠ clean" on high-risk surfaces (proof obligations — bounded/index-supported DB reads, aggregation stage order, platform limits) balanced by its mirror "not proven broken ≠ broken" (a finding carries the same proof burden as the stamp — trace broken before you assert it, hedge if you can't; the burden is re-charged **every round**, so a finding surviving an author dispute must re-earn its severity on the current head, and a blocker that can only be stated in future tense — "unbounded as it grows" — is a follow-up, not a blocker), a five-kind author-dispute taxonomy each with its own check (a prescribed fix proven impossible **voids** the finding until re-derived), a durable field-lessons trigger scan with live-chain, writer-set, predicate, parity, and visible-outcome proofs, a **reachability grid** proof obligation (every entry point × lifecycle of a changed unit enumerated in the receipts before it is judged — an unenumerated cell is unreviewed, not safe; the generic form of five recorded blind spots), the same burden charged on *prescriptions* (prove no legitimate caller produces the state you tell the author to reject — a fix that forks on an unchecked fact is not a fix), lizard's own requested change reviewed as new code and never graded "prior finding resolved ✓" (the fix lizard demands is the highest-asymmetry stamp there is — it wrote the requirement and now grades it, so an outage there is one it authored rather than missed), closure enumeration before **every** non-approval rather than only the first, late findings disclosed as the reviewer's miss rather than the author's damage, and same-head human-review disagreements graded back into blind spots and eval coverage, claims cross-checked against linked Linear/Notion/issue context, every finding inline + actionable, collapsed receipts toggle (always a two-column `<details>` table — plain bullet receipts invalid), fingerprint dedup + delta re-review + parallel-run guard (at most one standing verdict per head — own-account 👀 in-flight claim, pre-POST re-check, later duplicate yields), `~/.lizard/` ledger + mandatory blind-spot entries, `lizard retro` for post-merge calibration. Posts as you (self-authored PRs get stamp-as-comment). Session (`lizard <pr>`), loop (`lizard sweep`), or routine; agent-agnostic (git + gh + markdown). Easter egg — "why lizard". **`--local [<base>]`** reviews a branch with no PR (base = default branch), skips dedup/claim/posting, and prints the verdict plus the `LIZARD_PAYLOAD` block; shepherd and Arnold call it. Loading is lazy: startup fetch lives in SKILL.md, `github-review-api.md` loads only at post time, `re-review.md` only when a prior review exists, and the old `field-lessons.md` is split into four triggered `focus-packs/lessons-*.md` packs plus criteria §8 (review mechanics). One pack-trigger table in SKILL.md picks packs without opening them. |

The forge suite (18 skills) lives in `skills/` and installs by default. Every stage
builds to `forge-principles` and ends with a `FORGE_RESULT` line. Cross-skill paths
are literal and relative to the skill folder (`../forge/references/…`); the validator
checks them. Install everything with `npx skills add tinyorbit-ai/skills --all`.
